## Repeatable source and bundle checks

Run from the intended integrated revision with Node 22+ and locked dependencies:

```sh
npm test
npm run build
node scripts/check-build-mode.mjs release
npm run build:dev
node scripts/check-build-mode.mjs development
# After Markdown integration and generator page registration:
npm run docs:build
npm run docs:check
```

Record command exit status, source SHA and actual test totals in the final release record. Do not copy intermediate totals into a final claim. `build` and `build:dev` both replace `dist/`; rebuild the intended final artifact before preparing Pages. CI checks release exclusion first, then checks/packages the explicit development build with QA. The artifact inspector rejects QA chunk/signature presence in release, and requires QA JavaScript/CSS plus expected signatures in development.

Targeted checks identify useful ownership boundaries:

```sh
node --test tests/surfaces.test.js tests/world-geometry.test.js tests/goal-view.test.js
node --test tests/delivery.test.js tests/ui.test.js tests/progression.test.js
node --test tests/cutaway.test.js tests/render.test.js tests/qa.test.js
node --test tests/deploy-pages.test.js tests/herding-journey.test.js
```

These tests use actual production modules and real Three.js geometry/matrices behind substituted browser/graphics/audio surfaces. Synthetic position fixtures verify state/geometry and are distinct from ordinary-input herding journeys. None measures actual rendered pixels, phone FPS, human timing or sound quality.
